How to run the demo

  1. Start the mock bot (separate server process): node mock-ig-bot/server.js — listens on http://127.0.0.1:8904 by default.
  2. Serve this folder: python3 -m http-server 8000 from app/, then open http://localhost:8000/mock-dm.html.
  3. The demo token SYNTH_mock_token is prefilled below (non-secret demo value; the real bot token never goes here).
  4. Live mode (real Instagram bot, same computer only): start with LIVE_IG=1 sh start.sh from the repo root, then open http://localhost:8000/mock-dm.html — or the remote (Tailscale) link to this same server. Either address works: the page only ever talks to its own origin (relative /ig and /api paths) and the live-proxy on this server hops to the bot from there, so there is no cross-origin or mixed-content request for the browser to block.

How to share a photo

Pick an image file below (or drag-drop it onto the thread) and hit Share. The photo is injected into the mock as an inbound share (POST /mock/incoming-photo) and appears as an incoming bubble. Type a message below to add an inbound text turn (POST /mock/incoming-text). Either trigger is answered in-thread with a full-look bubble, never a standalone card panel.

How to trigger a send-as-app

Pick the share to reply to, type the reply text (and optionally stage a share-card image), then hit “Send as app”. The page issues a byte-identical POST /ig/send with "confirm": true; the text appears as an outgoing bubble, fed by the mock’s own send handler.

How to propose a full look as a bubble

Pick the share to reply to, fill in the look title, the fit-rule verdict line, and one line per piece, then optionally attach the look preview image. “Propose look” stages that image with POST /mock/stage-outbound-image/<share_id> and then sends the turn with POST /ig/send {"image": true}. The thread renders the result as one outgoing bubble: text part first (title + fit note + per-piece lines within the shared 300-word budget), staged-image part second.

Stale-share + duplicate-send demos

“Inject stale share” below adds a share backdated 30 hours: sending to it honestly returns 422 reply_window_expired. Sending the same text twice (with a fresh key each time) returns 409 duplicate_send; ticking “reuse last idempotency key” and re-sending replays the stored result instead.
